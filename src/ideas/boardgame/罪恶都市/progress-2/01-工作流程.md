# 罪恶都市 · AI Agent 工作流程（progress-2）

> 本文档为 AI agent 提供完整的、逐步执行的工作流程。
> 每次"推进"执行一个方案的当前阶段所有未完成任务。

---

## 核心规则

1. **批量推进**：每次"推进"执行一个方案的当前阶段所有未完成任务
2. **执行顺序**：A 全部完成 → B 全部完成 → C 全部完成（同一阶段内按此顺序）
3. **进度记录**：每个方案的当前阶段所有任务完成后，更新 `02-进度监控.md` 和 `03-任务执行记录.md`
4. **结果可验证**：每个任务产出明确的文档或文件
5. **🚨 硬性停机规则**：每次推进完成后，必须使用 `attempt_completion` 工具报告结果并**完全停止**，绝不可自行继续下一轮推进。必须等待用户再次输入"推进"指令后再启动新一轮工作。
6. **独立创作**：三个方案各自独立进行，从各自的方向描述出发，从零创作，彼此不引用。

## 阶段 1：概念设计（每个方案独立进行）

> 每个方案独立完成本阶段所有任务。
> 执行顺序：A 的 1.1-1.5 全部完成 → B 的 1.1-1.5 全部完成 → C 的 1.1-1.5 全部完成
> 任务间有依赖关系，须按 1.1→1.2→1.3→1.4→1.5 顺序执行。

**目标**：给出方案的一句话概念、核心卖点、目标体验。

**输入**：

## 阶段 1.5：阶段 1 评审（每个方案独立进行后执行）

> 本阶段在方案 A/B/C 的阶段 1 全部完成后执行，**仅执行一次**。
> 产出评审文档，为阶段 2 的详细设计提供修改方向和设计原则参考。

### 任务 R.1：三方案评价与修改建议

**目标**：以资深桌游设计师视角，对三个方案（A/B/C）的阶段 1 全部产出进行全方位评价，给出具体的修改建议。

**输入**：

- 方案 A：draft-2-A/01~05（阶段 1 全部产出）
- 方案 B：draft-2-B/01~05（阶段 1 全部产出）
- 方案 C：draft-2-C/01~05（阶段 1 全部产出）

**产出**：`draft-2-X/评审-概念设计.md`（每个方案独立，写入各自目录）

**评价维度**（至少覆盖）：

- 概念与定位符合度
- 核心机制自洽性
- 主题契合度
- 非对称平衡性
- 轻策匹配度
- 创新性亮点
- 潜在风险预判

**检查清单**：

- [ ] 对每个方案的 7 维度评价
- [ ] 按优先级（🔴高/🟡中/🟢低）给出具体修改建议
- [ ] 三方案横向对比总结
- [ ] 进入阶段 2 前必须明确的决策点

### 任务 R.2：用户安利对话反馈记录

**目标**：以"朋友安利"方式向用户逐一介绍三个方案，记录用户的真实反馈和质疑，提炼设计原则和判断标准。

**输入**：

- 方案 A：draft-2-A/01~05
- 方案 B：draft-2-B/01~05
- 方案 C：draft-2-C/01~05
- 任务 R.1 的产出（如有，用于支撑评价）

**执行方式**：

- 以熟悉该桌游的口吻向用户介绍每个方案的玩法和亮点
- 与用户进行多轮对话，回答质疑，解释设计
- 用户表现出不耐烦时及时切换话题或结束

**产出**：`refs/user-feedback-2.md`

**检查清单**：

- [ ] 记录用户对每个方案的第一印象和关键词
- [ ] 记录用户的核心质疑和关键判断
- [ ] 提炼设计原则（什么好玩、什么无聊、为什么）
- [ ] 总结对后续设计的指导建议

### 阶段 1.5 完成后

1. 将 `draft-2-{A/B/C}/评审-概念设计.md` 和 `refs/user-feedback-2.md` 注册到"参考文档清单"中（更新 01-工作流程.md）
2. 更新 `02-进度监控.md` 标记阶段 1.5 完成
3. 更新 `03-任务执行记录.md` 记录本次推进

## 任务执行流程（主 agent 每次"推进"时遵循）

```
1. 读取 progress-2/03-任务执行记录.md
   → 确定当前轮到哪个方案（A/B/C）
   → 确定该方案当前阶段的所有未完成任务列表

2. 读取 progress-2/02-进度监控.md
   → 确认任务状态为"待执行"

3. 确定本次推进的任务列表（同一方案、同一阶段的所有未完成任务）

4. 按顺序依次执行每个任务
   → 每个任务：读取输入资料 → 生成文档 → 使用 write_to_file 写入产出
   → 阶段 1 中：1.1→1.2→1.3→1.4→1.5 按序（有依赖关系）
   → 阶段 2 中：2.1→2.2→2.3→2.4 按序（有依赖关系）
   → 阶段 3 中：3.1~3.4 无依赖关系，按任意顺序

5. 每个任务的方案方向引用：
   - 方案 A：读取 refs/user-ideas-2-A.md
   - 方案 B：读取 refs/initial-gpt.md 和 refs/user-ideas-2-B.md
   - 方案 C：无额外 refs 要求
   - 阶段 1.5（R.1 和 R.2）：读取三个方案的阶段 1 全部产出

6. 当前阶段所有任务执行完毕后
   → 更新 progress-2/02-进度监控.md（标记该方案当前阶段所有任务已完成）
   → 更新 progress-2/03-任务执行记录.md（记录执行详情）

7. 报告完成并停机
   → 使用 attempt_completion 工具向用户报告本轮推进完成
   → 🚨 必须完全停止，不可执行任何下一步工作
   → 等待用户下一次"推进"指令
