# 罪恶都市 · AI Agent 工作流程（progress-2 · subagent 模式）

> 本文档为 AI agent 提供完整的、逐步执行的工作流程。
> 每次"推进"执行一个方案的当前阶段所有未完成任务。
> 每个任务由独立的 subagent 执行，执行完毕后 subagent 关闭。

---

## 核心规则

1. **批量推进**：每次"推进"执行一个方案的当前阶段所有未完成任务
2. **执行顺序**：A 全部完成 → B 全部完成 → C 全部完成（同一阶段内按此顺序）
3. **subagent 执行**：每个任务启动一个独立的 subagent，执行完毕后 subagent 关闭
4. **进度记录**：每个方案的所有 subagent 执行完毕后，更新 `02-进度监控.md` 和 `03-任务执行记录.md`
5. **结果可验证**：每个任务产出明确的文档或文件
6. **🚨 硬性停机规则（AI agent 必须遵守）**：每次推进完成后，必须使用 `attempt_completion` 工具报告结果并**完全停止**，绝不可自行继续下一轮推进。必须等待用户再次输入"推进"指令后再启动新一轮工作。
7. **独立创作**：三个方案各自独立进行，从各自的方向描述出发，从零创作，彼此不引用。

## 阶段 1：概念设计（每个方案独立进行）

> 每个方案独立完成本阶段所有任务。

**目标**：给出方案的一句话概念、核心卖点、目标体验。

## 阶段 1.5：阶段 1 评审（每个方案独立进行后执行）

> 本阶段在方案 A/B/C 的阶段 1 全部完成后执行，**仅执行一次**。
> 产出评审文档，为阶段 2 的详细设计提供修改方向和设计原则参考。
> 执行顺序：R.1 和 R.2 可并发执行（无依赖关系）。

### 任务 R.1：三方案评价与修改建议

**目标**：以资深桌游设计师视角，对三个方案（A/B/C）的阶段 1 全部产出进行全方位评价，给出具体的修改建议。

**输入**：

- 方案 A：draft-2-A/01~05（阶段 1 全部产出）
- 方案 B：draft-2-B/01~05（阶段 1 全部产出）
- 方案 C：draft-2-C/01~05（阶段 1 全部产出）

**产出**：`progress-2/06-方案评价与修改建议.md`

**评价维度**（至少覆盖）：

- 概念与定位符合度
- 核心机制自洽性
- 主题契合度
- 非对称平衡性
- 轻策匹配度
- 创新性亮点
- 潜在风险预判

**检查清单**：

- [ ] 对每个方案的 7 维度评价
- [ ] 按优先级（🔴高/🟡中/🟢低）给出具体修改建议
- [ ] 三方案横向对比总结
- [ ] 进入阶段 2 前必须明确的决策点

**参考格式**：本次执行产生的 `progress-2/06-方案评价与修改建议.md` 本身就是该任务的执行范例。后续新项目可参照其结构和评价维度执行。

### 任务 R.2：用户安利对话反馈记录

**目标**：以"朋友安利"方式向用户逐一介绍三个方案，记录用户的真实反馈和质疑，提炼设计原则和判断标准。

**输入**：

- 方案 A：draft-2-A/01~05
- 方案 B：draft-2-B/01~05
- 方案 C：draft-2-C/01~05
- 任务 R.1 的产出（如有，用于支撑评价）

**执行方式**：

- 以熟悉该桌游的口吻向用户介绍每个方案的玩法和亮点
- 与用户进行多轮对话，回答质疑，解释设计
- 用户表现出不耐烦时及时切换话题或结束

**产出**：`refs/user-feedback-2.md`

**检查清单**：

- [ ] 记录用户对每个方案的第一印象和关键词
- [ ] 记录用户的核心质疑和关键判断
- [ ] 提炼设计原则（什么好玩、什么无聊、为什么）
- [ ] 总结对后续设计的指导建议

## subagent 任务执行规范

### subagent prompt 模板

每个 subagent 执行时，主 agent 通过 `use_subagents` 工具启动，传入完整的上下文。subagent 的 prompt 应包含以下内容：

```
## 任务描述
[任务编号]：[任务名称]

## 方案方向
方案 [A/B/C] · draft-2-X
方向说明：[方案 A/B/C 的方向描述]

## 输入资料
- [需要读取的已有文档列表]
- 参考文档清单（见 01-工作流程.md 中"参考文档清单"章节）：按"影响范围"列判断是否需要读取

与阶段相关的通用参考文档：
- 阶段 1：不需要读取设计方案评价和用户反馈（阶段 1 为从零创作）
- 阶段 2 及以上：必须读取 progress-2/06-方案评价与修改建议.md（重点关注该方案对应的 🔴 高优先级建议）和 refs/user-feedback-2.md（重点关注"设计原则提炼"章节）

## 产出要求
- 文件路径：draft-2-X/[产出文件名]
- 需遵循的检查清单：[详见本工作流程文档]
```

### subagent 执行流程

```
1. subagent 启动
2. subagent 读取输入资料
3. subagent 生成产出文档并写入文件系统
4. subagent 报告完成
5. subagent 结束（关闭）
```

### 注意事项

- 每个 subagent 只执行一个任务
- 如果任务间存在依赖（如 1.2 依赖 1.1，2.2 依赖 2.1），必须按顺序启动
- subagent 执行完毕后，主 agent 负责检查产出文件是否存在
- subagent 能够使用 write_to_file 工具自行写入产出文件

## 任务执行流程（主 agent 每次"推进"时遵循）

```
1. 读取 progress-2/03-任务执行记录.md
   → 确定当前轮到哪个方案（A/B/C）
   → 确定该方案当前阶段的所有未完成任务列表

2. 读取 progress-2/02-进度监控.md
   → 确认任务状态为"待执行"

3. 确定本次推进的任务列表（同一方案、同一阶段的所有未完成任务）

4. 依次启动 subagent 执行每个任务
   → 阶段 1 中：1.1→1.2→1.3→1.4→1.5 必须按序启动（有依赖关系）
   → 阶段 1.5 中：R.1 和 R.2 可并发启动（无依赖关系）
   → 阶段 2 中：2.1→2.2→2.3→2.4 必须按序启动
   → 阶段 3 中：3.1→3.2→3.3→3.4 可并发启动（无依赖关系）

5. 每个 subagent 的 prompt 中需包含方案方向描述（A/B/C 各不同）
   - 方案 A：告知"读取 refs/user-ideas-2-A.md 中的用户补充设计方向"
   - 方案 B：告知"读取 refs/initial-gpt.md 和 refs/user-ideas-2-B.md"
   - 方案 C：无额外 refs 要求
   - 阶段 1.5（R.1 和 R.2）：需要读取三个方案的阶段 1 全部产出

6. 所有 subagent 执行完毕后
   → 更新 progress-2/02-进度监控.md（标记该方案当前阶段所有任务已完成）
   → 更新 progress-2/03-任务执行记录.md（记录执行详情）

7. 报告完成并停机
   → 使用 attempt_completion 工具向用户报告本轮推进完成
   → 🚨 必须完全停止，不可执行任何下一步工作
   → 等待用户下一次"推进"指令
