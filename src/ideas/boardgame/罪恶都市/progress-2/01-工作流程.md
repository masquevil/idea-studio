# 罪恶都市 · AI Agent 工作流程（progress-2 · subagent 模式）

> 本文档为 AI agent 提供完整的、逐步执行的工作流程。
> 每次"推进"执行一个方案的当前阶段所有未完成任务。
> 每个任务由独立的 subagent 执行，执行完毕后 subagent 关闭。

---

## 核心规则

1. **批量推进**：每次"推进"执行一个方案的当前阶段所有未完成任务
2. **执行顺序**：A 全部完成 → B 全部完成 → C 全部完成（同一阶段内按此顺序）
3. **subagent 执行**：每个任务启动一个独立的 subagent，执行完毕后 subagent 关闭
4. **进度记录**：每个方案的所有 subagent 执行完毕后，更新 `02-进度监控.md` 和 `03-任务执行记录.md`
5. **结果可验证**：每个任务产出明确的文档或文件
6. **🚨 硬性停机规则（AI agent 必须遵守）**：每次推进完成后，必须使用 `attempt_completion` 工具报告结果并**完全停止**，绝不可自行继续下一轮推进。必须等待用户再次输入"推进"指令后再启动新一轮工作。
7. **独立创作**：三个方案各自独立进行，从各自的方向描述出发，从零创作，彼此不引用。

---

## 方案方向说明

所有方案共享基本设定：警匪非对称对抗、围绕城市地点展开行动、卡牌驱动、轻策桌游。多阵营（警长、罪犯、超级英雄、受害者联盟），每人各自为战。

| 方案 | 目录 | 核心方向 |
|------|------|---------|
| **A** | draft-2-1 | **德式轻策**：以资源控制规划为主，轻度对抗，类似伯明翰的对抗程度 |
| **B** | draft-2-2 | **参考 refs**：基于 refs/initial-gpt.md 的 GPT 讨论（唯一需要读外部文件） |
| **C** | draft-2-3 | **自由发挥**：无约束，完全自由创作 |

## 阶段 1：概念设计（每个方案独立进行）

> 每个方案独立完成本阶段所有任务。
> 执行顺序：A 的 1.1-1.5 全部完成 → B 的 1.1-1.5 全部完成 → C 的 1.1-1.5 全部完成

### 任务 1.1：原始点子

**目标**：给出方案的一句话概念、核心卖点、目标体验。

**输入**：

- 方案 A：方向为**德式轻策**——资源控制规划为主，轻度对抗，类似伯明翰的对抗程度。从零构思。
- 方案 B：读取 `refs/initial-gpt.md` 作为参考，提炼核心概念。
- 方案 C：自由发挥，从零构思。

**产出**：`draft-2-X/01-原始点子.md`

**检查清单**：

- [ ] 一句话概念（30字以内）
- [ ] 核心卖点（3-5个关键词）
- [ ] 目标体验（玩家玩完后的感受）
- [ ] 与方案方向说明的关联

### 任务 1.2：核心机制设计

**目标**：基于该方案的方向和原始点子，定义核心游戏循环、胜利条件、基本规则框架。

**输入**：

- 该方案已产出的 01-原始点子.md

**产出**：`draft-2-X/02-核心机制.md`

**检查清单**：

- [ ] 核心游戏循环（玩家每回合做什么）
- [ ] 胜利条件（各阵营如何获胜）
- [ ] 基本规则框架

## subagent 任务执行规范

### subagent prompt 模板

每个 subagent 执行时，主 agent 通过 `use_subagents` 工具启动，传入完整的上下文。subagent 的 prompt 应包含以下内容：

```
## 任务描述
[任务编号]：[任务名称]

## 方案方向
方案 [A/B/C] · draft-2-X
方向说明：[方案 A/B/C 的方向描述]

## 输入资料
[需要读取的已有文档列表，方案 B 的 1.1 需额外读取 refs/initial-gpt.md]

## 产出要求
- 文件路径：draft-2-X/[产出文件名]
- 需遵循的检查清单：[详见本工作流程文档]
```

### subagent 执行流程

```
1. subagent 启动
2. subagent 读取输入资料
3. subagent 生成产出文档并写入文件系统
4. subagent 报告完成
5. subagent 结束（关闭）
```

### 注意事项

- 每个 subagent 只执行一个任务
- 如果任务间存在依赖（如 1.2 依赖 1.1，2.2 依赖 2.1），必须按顺序启动
- subagent 执行完毕后，主 agent 负责检查产出文件是否存在
- subagent 能够使用 write_to_file 工具自行写入产出文件

## 任务执行流程（主 agent 每次"推进"时遵循）

```
1. 读取 progress-2/03-任务执行记录.md
   → 确定当前轮到哪个方案（A/B/C）
   → 确定该方案当前阶段的所有未完成任务列表

2. 读取 progress-2/02-进度监控.md
   → 确认任务状态为"待执行"

3. 确定本次推进的任务列表（同一方案、同一阶段的所有未完成任务）

4. 依次启动 subagent 执行每个任务
   → 阶段 1 中：1.1→1.2→1.3→1.4→1.5 必须按序启动（有依赖关系）
   → 阶段 2 中：2.1→2.2→2.3→2.4 必须按序启动
   → 阶段 3 中：3.1→3.2→3.3→3.4 可并发启动（无依赖关系）

5. 每个 subagent 的 prompt 中需包含方案方向描述（A/B/C 各不同）
   方案 B 的 B.1.1 原始点子还需告知"读取 refs/initial-gpt.md"

6. 所有 subagent 执行完毕后
   → 更新 progress-2/02-进度监控.md（标记该方案当前阶段所有任务已完成）
   → 更新 progress-2/03-任务执行记录.md（记录执行详情）

7. 报告完成并停机
   → 使用 attempt_completion 工具向用户报告本轮推进完成
   → 🚨 必须完全停止，不可执行任何下一步工作
   → 等待用户下一次"推进"指令
