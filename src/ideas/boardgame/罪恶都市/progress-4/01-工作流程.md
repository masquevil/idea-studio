# 罪恶都市 · AI Agent 工作流程（progress-4）

> 本文档为 AI agent 提供完整的、逐步执行的工作流程。
> 每次"推进"执行一个细分任务。
> 每个阶段内部遵循「产出 → AI 评审 → 用户反馈 → 修改」的迭代循环。

---

## 🚨 核心规则

### 1. 逐任务推进

每次**你（用户）说"推进"**时，AI agent 只执行**一个细分任务**，然后立即停机等待下一次指令。

### 2. 推进完成后停机

每次推进完成后，AI agent 必须使用 `attempt_completion` 工具报告结果并**完全停止**，绝不可自行继续下一轮推进。必须等待用户再次输入"推进"指令后再启动新一轮工作。

### 3. "推进"与"对话"的区分

只有以下情况需要说"推进"：

| 切换 | 是否需要"推进" | 说明 |
| --- | --- | --- |
| ③-B → ③-C | ✅ 推进 | 评审完成后，切换至 PLAN MODE 呈现结果 |
| ③-C → ③-D | ❌ 不需要 | 在 ③-C 中用户直接说话给意见，AI 直接修改 |
| ③-D → ③-B | ✅ 推进 | 修改完成后，进入新一轮评审 |
| ③-D 内多次修改 | ❌ 不需要 | 用户分多次给意见时，直接说话即可，AI 直接修改 |

### 4. 阶段内迭代引擎

每个阶段内部遵循以下循环：

```
┌─────────────────────────────────────────────────────┐
│  阶段 N                                            │
│                                                     │
│  【推进】ACT MODE — 用户说"推进"                    │
│  → ③-A/AI 产出该阶段的完整内容                      │
│  → 停机等待                                        │
│                                                     │
│  【推进】ACT MODE — 用户说"推进"                    │
│  → ③-B/AI 以资深设计师视角评审当前内容              │
│  → 停机等待                                        │
│                                                     │
│  【推进】PLAN MODE — 用户手动切换后说"推进"         │
│  → ③-C/AI 呈现评审结果，询问你的反馈意见             │
│  → 你直接说话给出修改方向或确认没问题                │
│  → 停机等待（你切换回 ACT MODE）                    │
│       ↓（不需要说"推进"，直接说话）                   │
│  【你的反馈 ①】ACT MODE — 你说意见                   │
│  → AI 执行 ③-D 修改                                 │
│  → 停机等待                                        │
│       ↓（不需要说"推进"，直接说话）                   │
│  【你的反馈 ②】ACT MODE — 你说更多意见               │
│  → AI 继续修改                                      │
│  → 停机等待                                        │
│       ↓（任意多次）                                  │
│  【你说"推进"】                                      │
│  → 回到 ③-B 新一轮评审                              │
│       ↓                                             │
│  【循环】③-B→③-C→③-D→③-B→...                     │
│  直到在 ③-C 中你说"没问题"                          │
│  下一次"推进" → 进入下一阶段                        │
└─────────────────────────────────────────────────────┘
```

> **关键点**：③-C/③-D 循环内无论用户分多少次给意见、AI 分多少次修改，**都属于同一次循环，不递增推进编号**。完整的 B→C→D 才算一轮。

### 5. 🚨 推进 C（用户反馈）必须处于 PLAN MODE

- 执行推进 C 时，AI agent **必须处于 PLAN MODE**
- 如果当前是 ACT MODE，agent 必须：
  1. 提示用户"请切换到 PLAN MODE 以进行用户反馈"
  2. 使用 `attempt_completion` 结束当前推进
  3. 等待用户切换模式后重新"推进"

### 6. 用户确认后才进入下一阶段

- 在推进 C 中，你说"没问题"（或类似明确确认），才意味着当前阶段通过
- 下一次"推进"时，AI 进入下一阶段，从"产出"开始

### 7. 唯一方案

本工作流程仅设计 **draft-4-A** 一个方案。所有产出放在 `draft-4-A/` 目录下。不涉及多方案并行。

### 8. 核心参考文档

所有阶段的设计都基于 `refs/user-initial-4.md`（v4 原始想法）。AI 在每个任务的输入中都必须引用该文档，确保设计不偏离方向。

## 阶段 ①：概念定义

> 目标：基于 `refs/user-initial-4.md` 中的 v4 原始想法，提炼出概念卡片。

### 推进 ①-A：AI 产出概念卡片

**任务**：AI 以资深桌游设计师身份，基于 v4 原始想法，产出完整的概念卡片。

**输入资料**：

- `refs/user-initial-4.md`（v4 原始想法，核心参考）

**产出文档**：`draft-4-A/01-概念卡片.md`

**内容结构**：

1. **一句话 Hook**（30 字以内）
   - 格式：玩家扮演「身份」，通过「核心动作」达成「目标」，核心阻力是「冲突/张力」
   - 检验：念给非桌游玩家的朋友听，30 秒内对方能否产生期待

2. **锁定参数**
   - 玩家人数：2-7 人（精确表格式列出各人数配置）
   - 单局时长：30-120 分钟
   - 复杂度层级：轻中策
   - 核心机制类型：从 skill 主流类型中选择 1-3 个，说明理由
   - 游戏类型定位：非对称、卡牌驱动、跑分制

3. **设计继承说明**
   - 明确哪些 v4 想法直接保留
   - 明确哪些 v4 想法需要修改/细化/删除
   - 明确哪些 v4 想法暂不确定，留待后续阶段验证

4. **模糊假设清单**
   - 列出当前设计中的所有未确定假设
   - 例如："假设 2 人局体验与 4 人局一致"、"假设 12 回合固定局比先到 15 分更好"等
   - 这些假设将在后续阶段逐步验证或修正

### 推进 ①-B：AI 评审概念卡片

**任务**：AI 以资深桌游设计师视角，对概念卡片进行全方位评审。

**评审规则**：不参考历史评审记录，完全基于当前文档内容重新进行一轮完整评审。评审时对照 `refs/ai-writing-standards.md` 的自查清单，检查文档是否符合写作规范。

**输入资料**：

- `refs/user-initial-4.md`（原始想法）
- `draft-4-A/01-概念卡片.md`（刚产出的内容）

**产出文档**：`draft-4-A/r01-概念评审.md`

**评价维度**：

- [ ] Hook 是否清晰有力？30 秒内能产生期待吗？
- [ ] 参数设定是否合理（人数/时长/复杂度是否匹配）？
- [ ] 机制类型选择是否合适？
- [ ] 设计继承说明是否合理？
- [ ] 模糊假设清单是否有遗漏？

**输出格式**：

- 按优先级（🔴高/🟡中/🟢低）给出具体问题
- 给出总体判断：通过 / 有条件通过 / 不通过

### 推进 ①-C：用户反馈（PLAN MODE）

**任务**：AI 呈现概念卡片和评审结果，询问你的反馈意见。

**执行条件**：⚠️ **必须处于 PLAN MODE**

**内容**：

- 简要呈现概念卡片的要点
- 简要呈现评审中发现的 🔴/🟡 问题
- 询问你的看法：哪些地方你认可？哪些地方你觉得不对？有没有遗漏的想法？

**产出文档**：不需要产出文档。用户的口头/文字反馈即输入。

### 推进 ①-D：AI 根据反馈修改概念卡片

**任务**：AI 根据你在推进 ①-C 中的反馈，修改概念卡片。

**输入资料**：

- `refs/user-initial-4.md`（原始想法）
- `draft-4-A/01-概念卡片.md`（当前版本）
- `draft-4-A/r01-概念评审.md`（评审意见）
- 你在推进 ①-C 中的反馈

**产出**：更新 `draft-4-A/01-概念卡片.md`

> 然后进入循环：推进 ①-B → ①-C(PLAN) → [用户直接说话→AI修改] → 你说"推进"→ ①-B → ...
> 直到你在推进 ①-C 中说"没问题"
> 你说"没问题"后，下一次"推进"进入阶段 ②

## 阶段 ②：核心循环设计

> 目标：基于已确认的概念卡片，设计完整的核心循环方案。
> 前置条件：阶段 ① 已通过你的确认。

### 推进 ②-A：AI 产出核心循环方案

**输入资料**：

- `refs/user-initial-4.md`（原始想法）
- `draft-4-A/01-概念卡片.md`（已确认版本）

**产出文档**：`draft-4-A/02-核心循环.md`

**内容结构**：

1. **核心循环定义**
   - 用「接收 → 选择 → 解决 → 回应 → 传递」或自定义格式描述玩家的最小重复决策单元
   - 识别唯一的"最难决策点"（HDP）——玩家在每回合中最烧脑的那个选择
   - 诊断 HDP 的信息来源

2. **回合结构方案**
   - 回合顺序类型（固定顺序 / 渐进式传递 / 竞标顺序 / 同时选择 等）
   - 先手/顺序优势的补偿方案（如有）
   - 回合流程的"3-2-1"简化检查
   - 参考 v4 想法中的"傍晚→夜晚→黎明"三轮结构，决定是否保留、修改或重构

3. **胜利条件设计**
   - 终局触发条件（跑分制：先到 15 分 / 12 回合结束）
   - 胜负判定方式
   - 各阵营的得分途径详解
   - 胜利条件与核心循环的关系

4. **各阵营核心机制（基于 v4 想法细化）**
   - 警长核心玩法
   - 罪犯核心玩法
   - 超级英雄核心玩法（如有）
   - 受害者核心玩法（如有）
   - 非对称关系图：各阵营之间的互动与对抗

5. **虚拟罪犯机制（2-3 人局）**
   - 基于 v4 想法的细化设计方案

### 推进 ②-B：AI 评审核心循环方案

**任务**：AI 以资深桌游设计师视角评审核心循环方案。

**评审规则**：不参考历史评审记录，完全基于当前文档内容重新进行一轮完整评审。评审时对照 `refs/ai-writing-standards.md` 的自查清单，检查文档是否符合写作规范。

**输入资料**：

- `refs/user-initial-4.md`
- `draft-4-A/01-概念卡片.md`
- `draft-4-A/02-核心循环.md`（刚产出的内容）

**产出文档**：`draft-4-A/r02-核心循环评审.md`

**评价维度**：

- [ ] 核心循环听上去有趣吗？
- [ ] 最难决策点是否有策略深度？
- [ ] 回合结构方案是否合适？
- [ ] 胜利条件是否清晰且有驱动力？
- [ ] 各阵营机制是否自洽？
- [ ] 非对称关系是否平衡？

### 推进 ②-C：用户反馈（PLAN MODE）

同阶段 ① 的推进 C 逻辑。

### 推进 ②-D：AI 根据反馈修改核心循环

**输入资料**：

- 所有阶段 ② 的相关文档 + 你的反馈

**产出**：更新 `draft-4-A/02-核心循环.md`

> 循环直到你说"没问题"，然后进入阶段 ③

## 任务执行流程（AI agent 每次"推进"时遵循）

### 两文档的作用

| 文档 | 何时读取 | 何时写入 | 内容 |
| ------ | ------ | ------ | ------ |
| `02-进度监控.md` | 推进开始时 | 推进结束后 | 简短状态（推进编号、任务、模式、完成日期），帮助 AI 确认当前位置 |
| `03-任务执行记录.md` | 不读取 | 推进结束后 | 详细历史（做了什么、产出什么、用户反馈了什么），供日后追溯 |

### 执行步骤

```
0. 读取 refs/ai-writing-standards.md
   → 对照写作规范自查清单，确保本次产出符合标准

1. 读取 progress-4/02-进度监控.md
   → 确认当前位置（当前完成到哪个推进、下一个任务是什么）

2. 读取 progress-4/00-总览.md
   → 确认项目最新上下文

3. 读取该任务所需的输入资料（设计方案文档等）

4. 执行该任务：
   → 产出对应文档（write_to_file）
   → 产出后对照 ai-writing-standards.md 自查清单检查

5. 更新 progress-4/02-进度监控.md
   → 标记该任务为"已完成"
   → 只更新状态和日期，不写详细备注

6. 更新 progress-4/03-任务执行记录.md
   → 记录执行详情（产出了什么文档、修改了什么内容、用户反馈了什么）

7. 使用 attempt_completion 报告完成
   → 🚨 必须完全停止，不可执行任何下一步工作
   → 等待用户下一次"推进"指令
