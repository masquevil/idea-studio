# 罪恶都市 · AI Agent 工作流程（progress-3）

> 本文档为 AI agent 提供完整的、逐步执行的工作流程。
> 每次"推进"执行一个方案的当前阶段所有未完成任务。

---

## 核心规则

1. **批量推进**：每次"推进"执行一个方案的当前阶段所有未完成任务
2. **执行顺序**：A 全部完成 → B 全部完成（同一阶段内按此顺序）
3. **进度记录**：每个方案的当前阶段所有任务完成后，更新 `02-进度监控.md` 和 `03-任务执行记录.md`
4. **结果可验证**：每个任务产出明确的文档或文件
5. **🚨 硬性停机规则**：每次推进完成后，必须使用 `attempt_completion` 工具报告结果并**完全停止**，绝不可自行继续下一轮推进。必须等待用户再次输入"推进"指令后再启动新一轮工作。
6. **独立创作**：两个方案各自独立进行，从各自的方向描述出发，从零创作，彼此不引用。

**输入**：

- 核心机制脉络（发展链条、博弈结构、胜负逻辑）

## 阶段 1r：概念设计评审与修改迭代（2 轮）

> 本阶段在方案 A/B 的阶段 1d 全部完成后执行。
> 核心规则：进行 **2 轮评审+修改迭代**。评审按方案分别进行，一次推进只评价一个方案。
> ⚠️ 除 1r.2（用户安利对话）外，所有推进只读取当前方案的文档，不读取另一个方案的任何文档。
> 评审文档覆盖同一文件（`评审-概念设计.md`），轮次信息由 `03-任务执行记录.md` 追溯。
> 产出供阶段 2d 使用。

---

### 🚨 核心规则：方案隔离

- **1r.1A / 1r.1B**：一次推进只读取一个方案的阶段 1d 产出，**不读取另一个方案的任何文档**
- **1r.2（用户安利对话）**：**唯一例外**，需要同时读取两个方案的文档
- **1r.3A / 1r.3B**：一次推进只修改一个方案的阶段文档，只读该方案的评审和反馈
- **方案引用规则**：
  - 方案 A 始终读取 `refs/user-ideas-2-B.md` 和 `refs/ref-draft-2-B.md`
  - 方案 B 始终仅读取 `refs/user-ideas-2-B.md`（不读 draft-2-B 任何内容）

---

### 🚨 1r.2 执行条件：必须处于 PLAN MODE

> 执行任务 1r.2 时，agent **必须处于 PLAN MODE**。
> 如果当前是 ACT MODE，agent 必须：
>
> 1. 提示用户"请切换到 PLAN MODE 以执行用户安利对话"
> 2. 使用 `attempt_completion` 结束当前推进
> 3. 等待用户切换模式后重新"推进"

### 任务 1r.2：用户安利对话反馈记录

**目标**：以"朋友安利"方式向用户逐一介绍两个方案，记录用户的真实反馈和质疑，提炼设计原则和判断标准。

**执行条件**：⚠️ **必须处于 PLAN MODE**（详见上方说明）

**输入**：

- 方案 A/B 的当前阶段产出（同时读取两个方案的文档）
- 该轮次的 1r.1A 和 1r.1B 的产出（如有）

**执行方式**：

- 以熟悉该桌游的口吻向用户介绍每个方案的玩法和亮点
- 与用户进行多轮对话，回答质疑，解释设计
- 用户表现出不耐烦时及时切换话题或结束

**产出**：`refs/user-feedback-3.md`（覆盖同一文件）

**检查清单**：

- [ ] 记录用户对每个方案的第一印象和关键词
- [ ] 记录用户的核心质疑和关键判断
- [ ] 提炼设计原则（什么好玩、什么无聊、为什么）
- [ ] 总结对后续设计的指导建议

### 🚨 核心规则：方案隔离

- **2r.1A / 2r.1B**：一次推进只读取一个方案的阶段 1d+2d 产出，**不读取另一个方案的任何文档**
- **2r.2A / 2r.2B**：一次推进只修改一个方案的阶段 2d 文档，只读该方案的评审
- **方案引用规则**：
  - 方案 A 始终读取 `refs/user-ideas-2-B.md` 和 `refs/ref-draft-2-B.md`
  - 方案 B 始终仅读取 `refs/user-ideas-2-B.md`（不读 draft-2-B 任何内容）

### 任务 2r.1A：方案 A 详细设计评价

**目标**：以资深桌游设计师视角，对方案 A 的阶段 2d 全部产出进行全方位评价，给出具体的修改建议。

**输入**：

- 方案 A 的阶段 1d 全部产出（draft-3-A/01~05）
- 方案 A 的阶段 2d 全部产出（draft-3-A/06~09）
- draft-3-A/评审-概念设计.md（该方案的 🔴/🟡 建议）
- refs/user-feedback-3.md
- 方案 A 上一轮评审文档（第 2 轮时，用于检查修改落实情况）
- **不读取方案 B 的任何文档**

**产出**：`draft-3-A/评审-详细设计.md`（覆盖同一文件）

**评价维度**（至少覆盖）：

- 配件与卡牌设计的可实现性（印刷、物理操作）
- 规则书完整性与清晰度
- 数值平衡性与阶段 1d 设计目标的符合度
- 核心机制可玩性（流程是否流畅）
- 非对称体验满意度
- 阶段 1r 评审建议的落实情况
- 进入阶段 3 前必须解决的修改项
- 上一轮修改建议落实情况（第 2 轮时新增此维度，可做简要记录）

**检查清单**：

- [ ] 对方案的 7 维度评价
- [ ] 按优先级（🔴高/🟡中/🟢低）给出具体修改建议
- [ ] 与阶段 1d 设计目标的对比总结
- [ ] 进入阶段 3 前必须明确的决策点

### 任务 2r.2A：根据评审结果修改方案 A 的详细设计

**目标**：根据最新评审文档的 🔴/🟡 建议，修改方案 A 的阶段 2d 文档（06-09）。

**检查清单**：

## 任务执行流程（主 agent 每次"推进"时遵循）

```
1. 读取 progress-3/03-任务执行记录.md
   → 确定当前轮到哪个方案/轮次
   → 确定该方案/轮次当前阶段的所有未完成任务列表

2. 读取 progress-3/02-进度监控.md
   → 确认任务状态为"待执行"

3. 确定本次推进的任务列表（同一方案、同一阶段的所有未完成任务）

4. 按顺序依次执行每个任务
   → 每个任务：读取输入资料 → 生成文档 → 使用 write_to_file 写入产出
   → 阶段 1d 中：1d.1→1d.2→1d.3→1d.4→1d.5 按序（有依赖关系）
   → 阶段 2d 中：2d.1→2d.2→2d.3→2d.4 按序（有依赖关系）
   → 阶段 3 中：3.1~3.4 无依赖关系，按任意顺序
   → 阶段 1r/2r 特殊规则：
     · 🚨 方案隔离：1r.1A/1r.1B/1r.3A/1r.3B/2r.1A/2r.1B/2r.2A/2r.2B 每次推进只读取一个方案的文档，**不读取另一个方案的任何文档**
     · 🚨 PLAN MODE 强制：1r.2（用户安利对话）执行时必须处于 PLAN MODE。如果当前是 ACT MODE，提示用户切换并结束推进
     · 🚨 唯一例外：1r.2 需要同时读取两个方案的文档
     · 评审轮次（1r.1A/1r.1B 或 2r.1A/2r.1B）：一次推进只评价**一个**方案
     · 修改轮次（1r.3A/1r.3B 或 2r.2A/2r.2B）：一次推进只修改**一个**方案的文档

5. 每个任务的方案方向引用：
   - 方案 A：读取 refs/user-ideas-2-B.md 和 refs/ref-draft-2-B.md
   - 方案 B：仅读取 refs/user-ideas-2-B.md（不读 draft-2-B 任何内容）
   - 🚨 方案隔离规则：
     · 1r.1A / 1r.3A / 2r.1A / 2r.2A：**只读方案 A 的文档**，不读方案 B
     · 1r.1B / 1r.3B / 2r.1B / 2r.2B：**只读方案 B 的文档**，不读方案 A
     · 1r.2：**唯一例外**，同时读取两个方案的阶段性文档

6. 当前阶段所有任务执行完毕后
   → 更新 progress-3/02-进度监控.md（标记该方案当前阶段所有任务已完成）
   → 更新 progress-3/03-任务执行记录.md（记录执行详情）

7. 报告完成并停机
   → 使用 attempt_completion 工具向用户报告本轮推进完成
   → 🚨 必须完全停止，不可执行任何下一步工作
   → 等待用户下一次"推进"指令
