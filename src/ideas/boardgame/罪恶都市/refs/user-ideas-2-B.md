# 用户补充设计方向 · 方案 B（progress-2）

> 这些是用户提供的设计方向，subagent 在设计方案 B 时需要参考。
> 具体实现方式由设计师自行决定，不必照搬。

---

## 1. 地点随机性

- 每局游戏开始时，从地点池中随机抽取一定数量的地点牌
- 摆成可变排列构成"城市版图"（如 3×N 或 4×N 网格）
- 地点之间的相邻关系由摆放位置决定
- 确保每局城市布局不同

## 2. NPC 系统（作为资源）

- 地点可能附带 NPC token（如目击者、线人、店主、混混、政客等）
- NPC 可被警长"询问"（消耗行动获得线索或资源）
- NPC 可被罪犯"利用"（获得额外收益或掩护）
- NPC 的出现具有随机性：每局在哪些地点出现、出现什么类型是不确定的
- NPC 作为一种可争夺/可利用的资源，增加游戏的变量和策略深度

## 3. 罪犯发育思路

- 罪犯前期的核心行动是"踩点"——选择目标地点/目标人物进行侦查
- 踩点获得某种资源（如情报、工具、路线图等）
- 踩点会在该地点留下线索 token，供警长使用
- 后续在同一地点（或关联地点）犯罪时，可消耗前期积累的资源来提升成功率或收益
- 资源、线索、地点、卡牌之间的具体关系由设计师自行设计

## 4. 人数平衡规则

- 以 **1警长 vs 3罪犯** 为基准进行设计
- **2人局**（1警长 vs 1罪犯）：引入"虚拟罪犯"机制，自动按某种逻辑在地点放置线索 token，警长也可使用这些线索进行推理
- **3人局**（1警长 vs 2罪犯）：同样引入虚拟罪犯机制，补足至相当于 3 罪犯的线索产出
- 虚拟罪犯的行为逻辑由设计师自行定义（如固定模式/随机模式/简化规则）

## 5. 与方案方向的融合

以上设计方向应融入方案 B 的"参考 refs/initial-gpt.md"方向中。特别是罪犯发育思路与 GPT 讨论中的"隐藏行动→线索→推理"链条结合，形成完整的前期踩点→中期犯罪→后期追捕的体验曲线。
