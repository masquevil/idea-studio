# 核心循环设计方法论

## 什么是核心循环

核心循环（Core Loop）是玩家在每个回合/每个操作周期中重复的最小决策单元。它是游戏的"心脏"——如果核心循环无聊，整个游戏就无聊。

## 标准描述格式

使用以下格式描述核心循环：

```
[接收] → [选择] → [解决] → [回应] → [传递]
```

- **接收**：玩家在回合开始时获得什么信息/资源？（抽牌、看版图、接收提示等）
- **选择**：玩家在这个回合中做出的核心决策是什么？（选哪张牌、移动到哪、攻击谁等）
- **解决**：决策如何执行？结果如何产生？（出牌结算、执行行动、投骰判定等）
- **回应**：其他玩家如何响应？（对手调整策略、触发连锁反应等）
- **传递**：回合如何结束并进入下一个循环？（弃牌、补充资源、传递回合标记等）

### 示例

**Scythe**：

```
接收 → 查看自己版图和版面上的资源/位置
选择 → 选择 1 个行动（移动/升级/部署/交易/招募）和可选的基础行动
解决 → 执行选择行动，更新资源/位置
回应 → 其他玩家在各自回合做出应对
传递 → 回合结束，轮到下一位玩家
```

## 最难决策点诊断（HDP）

核心循环中必须有一个让玩家真正需要思考的决策点。找到它，确认它是否够"硬"。

### HDP 定位方法

1. 列出核心循环中玩家需要做的所有选择
2. 对每个选择问：不假思索地选 vs 认真思考后选，结果差异大吗？
3. 如果所有选择的结果差异都很小 → **没有真正决策点**，核心循环是虚的
4. 如果唯一有差异的选择是"猜对手会怎么走"且没有信息支撑 → **沦为运气**

### HDP 诊断矩阵

| HDP 类型 | 特征 | 是否合格 |
| - | - | - |
| 信息推理型 | 玩家基于可见信息推算出最优解 | ✅ 合格 |
| 风险权衡型 | 玩家在高回报高风险 / 低回报低风险之间抉择 | ✅ 合格 |
| 心理博弈型 | 玩家基于对对手的预判做决策（有支撑证据） | ✅ 合格 |
| 盲猜型 | 玩家没有任何信息可供参考，纯猜 | ❌ 不合格 |
| 无关紧要型 | 选 A 或选 B 结果几乎无差异 | ❌ 不合格 |
| 最优解固定型 | 有一招永远最好，不需要思考 | ❌ 不合格 |

### 信息支撑检验

对 HDP 问以下问题：

- 玩家做出这个决策时，桌面上有哪些信息可见？
- 这些信息足以让推理成立吗？还是说推理链中有断层？
- 如果玩家做错决策，复盘时能说出"我当时应该注意到 X"吗？

## 胜利条件设计

### 胜利条件与核心循环的关系

核心循环中的每一步应该都在让玩家"靠近胜利"。检查标准：

- **直接关联**：玩家执行核心循环中的行动，是否在累积胜利条件所需的要素？
- **策略分歧**：不同的胜利可能对应不同的核心循环路径吗？
- **终局感知**：玩家能感知到"我再做 X 次循环游戏就要结束了"吗？

### 常见胜利条件类型

| 类型 | 示例 | 适用场景 |
| ------ | ------ | --------- |
| 得分最高 | 终局累计分数 | 大多数欧式桌游 |
| 首个达成目标 | 率先到达终点/收集全套 | 竞速类游戏 |
| 淘汰对手 | 最后存活 | 对战类/区控类 |
| 完成秘密任务 | 完成任务卡上的条件 | 半合作/身份推理 |
| 合作生存 | 全员活过指定回合+达成共同目标 | 合作游戏 |

## 通用陷阱检查

- **循环太复杂**：核心循环包含超过 5 个子步骤→可能应该简化
- **循环太简单**：核心循环可以无脑重复→缺乏策略深度
- **决策点过多**：每回合超过 3 个真正需要思考的选择→导致分析瘫痪
- **胜利与循环脱节**：玩家在执行核心循环时感受不到自己在靠近胜利
