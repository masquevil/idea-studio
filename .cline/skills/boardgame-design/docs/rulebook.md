# 规则书写规范

## 规则书标准结构

规则书应严格遵循以下段落顺序，不可随意调换：

```
1. 概述 / 主题 Hook（1 段）
   → 一句话说明游戏是什么、玩家做什么、怎么赢

2. 组件说明
   → 列出所有组件，使用游戏中统一的名词

3. 游戏设置（Setup）
   → 带图解的步骤说明，从布局 → 发牌 → 起始资源

4. 核心概念
   → 解释游戏的核心机制和关键术语（玩家需要在读回合流程前先理解的概念）

5. 回合结构
   → 第一层：5 句话以内的回合概述（"你的回合分为三步：先 XX，再 XX，最后 XX"）
   → 第二层：详细分解每一步做什么

6. 行动详解
   → 每个行动/操作的详细说明

7. 终局条件与计分
   → 游戏何时结束、如何判定胜负

8. 变体规则（可选）
   → 人数变体、进阶规则等

9. FAQ
   → Q&A 格式，覆盖已知的边界情况
```

## 书写原则

### "先概述后细节"原则

每个节都先给一个一句话总结，再展开细节。例：

```
❌ 直接：在每个玩家的回合中，你可以选择移动你的棋子到相邻的格子……（细节轰炸）
✅ 先概述：你的回合分为三步：移动 → 行动 → 结束。
   然后细节：1. 移动：你可以将棋子移动到相邻的格子……
```

### 同一名词原则

- 同一个概念在整个规则书中只能用同一个词指代
- 不要在规则书中发明同义词（"卡牌"和"牌"交替使用也不行，统一用一个）
- 动作指令使用祈使句（"抽取 2 张牌"而非"玩家可以抽取 2 张牌"）

### 卡面文字简短原则

- 卡牌/角色卡上的能力文字是印刷文字，受卡片空间限制，只描述核心机制（做什么、花什么、得什么），尽量简短
- 边界情况、例外细节、条件说明归口到规则书正文或 FAQ，不写进卡面
- 若某能力的核心机制本身需要大量边界说明，优先简化机制本身，而非在卡面堆说明

### 术语管理

建立术语对照表，确保全书一致：

| 统一使用 | 避免使用 |
| --------- | --------- |
| 出牌阶段 | 宣告阶段、行动期 |
| 地点 | 区域、场所、位置 |
| 标记 | token、记号、指示物 |

## 边界条件检查清单

规则书完成后，检查以下边界条件是否都有定义：

- [ ] 牌库/弃牌堆为空时如何处理？
- [ ] 多个效果同时触发时，结算顺序是什么？
- [ ] 玩家无法执行某个必要行动时（如无牌可出）如何应对？
- [ ] 平局如何判定？
- [ ] 玩家的回合内是否可以主动弃牌/放弃行动？
- [ ] 效果描述是否有歧义？（"所有玩家"包括自己吗？"相邻"包含对角线吗？）
- [ ] 游戏开始时如果有起点不一致的设置，是否说明清楚了？
- [ ] 某个组件数量不够用时怎么办？

## FAQ 条目格式

每个 FAQ 条目使用一致的格式：

```
Q: [问题]
A: [回答]
   规则依据：[引用相关规则章节]
   - [可选] 例子：[具体场景说明]
```

### FAQ 编写时机

FAQ 不需要在第一次写规则书时就写完整。正确的时机：

1. **阶段 ③（MVP 构建）**：只写核心规则，FAQ 留空
2. **阶段 ④（测试后）**：将测试中出现的疑问和边界情况填入 FAQ
3. **阶段 ⑥（定稿前）**：整理所有 FAQ，确保覆盖所有已知边界情况

> FAQ 只收录"玩家读卡面/读规则时自然会产生疑问"的边界情况。本身清晰易懂的规则不写入 FAQ——FAQ 是规则解释的归口，不是规则的冗长化。

## 规则书检验标准

- [ ] 非设计师的朋友读完后能否自行设置和开始游戏？
- [ ] 每个术语在全书中是否保持一致？
- [ ] 所有边界条件是否都有定义？
- [ ] 有没有"设计师默认玩家会懂"的隐含假设？
- [ ] 所有卡牌/角色卡的能力文字是否能在一张卡片内容纳，且不翻规则书也能理解核心？
